# Threat model

The reviewed system includes public clients/API/portal, private provider services, customer Workers, untrusted customer builds from GitHub or managed source, Control/application databases, mail/files, diagnostics and SQL recovery. Threats include a malicious tenant/repository/dependency, stolen user/provider credential, forged webhook, operator error, provider outage and an ambiguous committed mutation. This is a source-grounded model, not a new penetration-test or live account-scope attestation.

Workers Logs stores the full request URL of each invocation, so a Control API request that carries a restricted value in its query (the portal handoff `request`, the provider callbacks' `code` and `state`, the browser-login callback) would be retained in invocation logs. The Control API, MCP and webhook-ingress Wrangler profiles therefore set `observability.logs.invocation_logs` to `false`; the live setting follows the next release that applies it, and only the Control API readback is performed after a release ([data classification](data-classification.md)).

## Failure and lifecycle

Authorization outages deny protected mutations rather than granting fallback authority. Provider uncertainty preserves a reconciliation obligation; durable leases/generations prevent a stale callback from overwriting newer state. Runtime-secret removal advances desired generation and removes the provider binding; project cleanup purges scoped encrypted records only after its authorized resource-removal observations. Database registration revocation removes decryptable URI data. Expired/terminal recovery inputs and archive capabilities follow their job/lifecycle contract. [Custody lifecycle](../auth-and-secrets.md#customer-runtime-secrets), [database/recovery lifecycle](../database.md#recovery-and-deletion).

Review this model whenever a new public surface, provider privilege, deployable, storage/key type, runtime binding or data flow changes. A demonstrated tenant escape, provider credential exposure, build escape, credit double-posting or unrecoverable archive requires investigation and release blocking through the existing operational rules. A change to the Core binding model (consumers reach the Core only through typed service capabilities, with no SQL surface and no database credential) or to the PGCF provider and credential boundary must be reviewed here before it ships.

The managed-source/remote changes are implemented source under [D426](../decisions/clients-and-public-content.md#d426). The 6 October Artifacts proof records disposable Dev US/EU operations and no credential values; it does not prove a Production release, native Worker binding or end-user conversation. Namespace jurisdiction, R2 placement, model/client processing and customer application data are separate boundaries; a US/EU namespace is not a claim that the entire chat runs in that region.

W25 adds a sender-resource-to-project trust boundary: an unrelated application must not send as another main domain merely because both projects share a workspace or delegated client. The approved controls are private-suffix-aware registrable-domain equality, current project-bound DNS proof, distinct selected-domain use/admin and target-project grants, runtime admission rechecks, exact sender policies and exclusive inbound ownership. Project deletion/transfer must detach admission without destroying sibling provider/key/DNS custody. Changed settings are frozen into a durable send identity so uncertain retries cannot silently send a different From/Reply-To. [Owning mail contract](../mail-and-recovery.md#same-domain-shared-sender-contract), W25 verification gates. These controls remain subject to source review and exact release/live acceptance; no new penetration-test claim is made.

W26's historical release/acceptance remains scoped to its Development and Production receipts, including the route-first stored-log correction. C3 adds source controls described by [D438](../decisions/domains-and-mail.md#d438), [D439](../decisions/delivery-and-operations.md#d439) and [D440](../decisions/domains-and-mail.md#d440): exact prefixed Storage origins bind organization/environment/data identity; stamped project and key/assignment checks remain independent, and duplicate cross-environment key digests fail closed. Malformed gateway-family hosts never reach public fetch. One Storage-owned native admission precedes either gateway's body/database work; its approximate per-location quota is not a globally strict project budget. Independent gateway-name denial guards are fingerprinted in the policy cohort.

The private named classes express capability roles intrinsically. Native Cloudflare readbacks omit props, so the old props-attestation criterion is **superseded, not passed**. Exact service/entrypoint and reviewed bundle identity replace it for `StorageGatewayRelayEntrypoint`, `MailEgressEntrypoint` and send-only `DatabaseMailEntrypoint`; arbitrary generic props declarations still require exact readback. The old strict Storage class remains unchanged for its limited rollback boundary. This does not turn the caller marker into a secret or give customer code authority to construct private bindings. Anyone able to create those platform bindings already controlled the previous marker value.

The attachment path authenticates the environment receiving key once before transfer. Around bounded CDN reads it rechecks current ownership, receiving-domain/lifecycle authority, content state and expiry; it does not periodically reauthenticate the key. It validates only trusted HTTPS CDN hosts, sends no provider bearer to them and follows no redirects. Stream deadline/cancel/expiry/size and close-once cleanup do not imply that bytes already delivered can be recalled. Before headers, failures use fixed statuses; afterward they terminate the stream and clients must require EOF. The exact four-ID request does not expose CDN URLs or provider credentials. [Mail lifecycle](../mail-and-recovery.md#inbound-content-and-delivery-lifetime).

Source/local workerd regressions establish executable controls, not a new penetration test or hosted acceptance. C3 retains the unpinned migration path and old customer bindings until C4; both rollback boundaries and exact old-head secret maintenance are explicit in D439. Provider publication, actual prefixed-host reachability and bounded real attachment acceptance require their own receipts. Current completion gates.

The [D453 single-OAuth candidate](../decisions/clients-and-public-content.md#d453) removes the extra post-login project-grant surface. New automatic proof creation cannot revive terminal disconnect or repin accepted ownership/billing epochs; current canonical role and immutable accepted-cap guards apply at delayed effects. Disconnect intent denies new work, while completed acknowledgement waits for admitted-use drain. Provider timeout/abort remains an uncertain external outcome, not proof of rollback. Combined race review, native existing-client acceptance and release remain tracked separately in implementation progress.

W37's Native source candidate adds application end users as a separate trust boundary from platform Owners. Trusted gateway scope, current Core source/origin/Paid/epoch authority, SQL realm/user revocation and distinct browser/session/admin entrypoints address tenant confusion and stale-route sessions. Independent logical schema/role/registry identities address Dev/Prod credential crossover; application business-data authorization remains the customer's responsibility. Provider-subject identity, explicit fresh-session linking, one-use mailbox/invitation proofs and token-discard constraints address account takeover. [Auth policy](../auth-and-secrets.md#customer-application-auth), [private database isolation](../database.md#native-auth-database-candidate).

Native origin withdrawal and restore retain authority outside delayed calls/restored SQL: pending policy acknowledgements fence new effects; offline restore generations remain in Core, and exact pinned archive/claim observation governs continuation. Restore/operator integration is still under final tests. Runtime local proofs do not establish hosted CPU/hash cost, cold latency, OAuth provider success, private ServiceRPC compatibility, logging settings or complete recovery. Final whole-candidate Astra review, hosted qualification and release remain gates. [Origin withdrawal](../storage-and-domains.md#native-auth-origin-withdrawal-candidate), [mail and recovery candidate](../mail-and-recovery.md#native-auth-mail-and-recovery-candidate), implementation progress.

The Native export uncertainty boundary now retains the first effect journal before one upload permit, uses a provider-expiry-protected `native-exports/` key and rechecks the original Owner/accepted MCP/billing authority before capture, preparation, dispatch and finish. Cleanup has separate bounded expiry or exact deletion authority and uses the same artifact-scoped serialized Sandbox; a busy executor fails closed. An uncertain missing payload is retired by a permanent conditional nonsecret marker that blocks a delayed original PUT. This marker is not literal object absence. Immutable effect/retirement facts and terminal deletion guards prevent job failure or actor revocation from hiding a pending payload. Unreleased pre-`0620` Native archives without that journal require explicit qualified reconciliation. ## Live Preview source boundary

W41 treats the entire dedicated project/environment VM as untrusted. Provider/Git/SQL/signing credentials stay in private Workers; only customer-owned environment values and public transport markers enter the guest. The real hosted start reported `landlock_abi`, so Linux users, in-VM tools, files and shim responses supply no security authority. Source paths, hashes and immutable accepted-event selection are checked outside the VM; no-follow/atomic mutations inside it are defensive delivery behavior. An acknowledgement cannot select a different tenant, environment, physical target, policy or capability and does not attest executing code. Formal publication never consumes preview filesystem state.

Backup data grants bind one Worker-selected object and operation with durable byte/request/part budgets and expiry. Actual request/response streams are bounded, and reconciliation respects in-flight transfer deadlines and unknown completion outcomes. The guest can corrupt its own cache but cannot obtain R2 control authority or choose another prefix. Funding denial or revocation aborts active operations and destroys the VM outside the serial queue; late SDK/helper results cannot publish source, backup or readiness. The earlier native local Landlock case remains historical evidence for that mechanism, not hosted qualification of this replacement boundary.

Native cookies use host-only `__Host-` names and per-preview/Auth-generation signing. The already-recorded shared-parent Public Suffix List owner action remains open (the live list checked on 16 November contains no `omh.st` private entries); arbitrary tenant JavaScript can therefore still set shared-parent non-Host cookies. This is an inherited browser-isolation release consideration, distinct from the guest VM boundary, and is not declared fixed by local HMR or Native-cookie tests. Hosted lifetime/kernel/usage and seven-fixture acceptance remain reserved release gates. [D608](../decisions/runtime-and-lifecycle.md#d608), existing owner actions, [Public Suffix List](https://publicsuffix.org/list/public_suffix_list.dat).
